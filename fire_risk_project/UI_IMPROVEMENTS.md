# 입력·결과 UI 개선 보고 (2026-10-12)

## 분석 및 수정 범위

현재 서비스는 React/Vite `frontend/src/main.jsx` → `frontend/src/api.js` → FastAPI `api.py` → `risk_engine.py` → CSV로 연결된다. 질문 적용 여부는 `/api/questions`의 `적용상태`를 사용한다. 평가·저장·조회·비교·현황 API와 SQLite 저장 방식은 유지했다. 기존 Streamlit `app.py`는 이번 수정 대상이 아니다.

## 1. 수정한 파일

- `frontend/src/main.jsx`: 입력·결과 컴포넌트 연결, 추가 조건 미응답 검사, 등급 색상 통일.
- `frontend/src/styles.css`: 질문·결과 카드, SVG 차트, 반응형 스타일.
- 신규 `frontend/src/assessment-inputs.jsx`, `assessment-result.jsx`: 아래 컴포넌트.
- 신규 `frontend/src/reference-data.json`: 기존 04 기준 DB와 검수 완료 03 사고 DB의 읽기 전용 사본.
- 신규 `frontend/scripts/sync-reference-data.py`: CSV에서 참고자료 사본 갱신. DB 수정 없음.
- 신규 `frontend/scripts/ui-check.mjs`: 실행 중인 테스트 API와 React 컴포넌트 검증.
- `UI_IMPROVEMENTS.md`: 이 보고서.

기존 UI 백업 및 보호 파일 SHA256: `backups/before_ui_19eda812/`.

## 2. 새 컴포넌트

AssessmentQuestionGroups, ConditionalQuestion, FireWatchConditions, RiskGauge, Ring, ResponseDistributionChart, TopRiskFactors, RecommendedActions, EvidencePanel. 결과 조합은 Assessment, 상세 표는 내부 RawTable을 사용한다.

## 3. 입력 화면

Q ID는 입력 키로 유지하고 실제 표시 순서대로 01부터 번호를 매긴다. 기본 위험조건 → 불티·화염 통제조치 → 감시자 배치 순서로 묶고, 추가 조건은 별도 영역에서 확인한다. Q002는 선행 질문 미응답 시 비활성 카드로 보여주며, 기존 API의 적용/조건제외 판정을 따른다. 종료 후 항목은 평가 제외 접기 영역으로 이동했다.

W 질문은 짧은 제목과 설명으로 나누고 원문은 판단 기준 보기에서 유지한다. W004의 적용하지 않음/적용/확인 필요는 기존 아니오/예/확인불가 값을 그대로 전송한다. 초기값은 선택하세요이며 W 질문을 명시적으로 모두 선택해야 평가할 수 있다. 미응답을 확인불가로 자동 변환하지 않는다. Q ID와 W ID는 보조정보에서만 확인한다.

## 4. 결과 화면

현장·일시·작업정보, 위험지수 원형 게이지, 등급, 평가/확인 필요/평가 제외 수를 표시한다. 응답 분포와 TOP 5를 2열로 구성하고 좁은 화면에서는 1열로 전환한다. 차트는 기존 SVG 방식을 재사용하여 의존성을 추가하지 않았다.

필요한 조치는 현재 점수 발생 또는 미확인 질문과 연결된 DB 문구를 표시한다. 법령·KOSHA·동일 작업ID 사고자료를 접기 영역으로 제공한다. 상세 계산은 기본 접힘 상태이며 원래 계산 열을 모두 유지한다. 최종판정 원문도 남긴다. 화재 발생확률로 표시하지 않으며 강제경고 0건 카드를 만들지 않았다.

## 6. 미구현 또는 제한적으로 구현한 항목

- 개별 응답의 안전/주의/위험 구분은 DB 기준이 없어 만들지 않았다. 0점/점수 발생/확인필요/평가제외로 표시한다. 0점은 안전 확정이 아니다.
- 조치 우선순위는 확정할 데이터가 없어 조치 검토/확인필요로 표시한다.
- 강제경고 판정은 기존 엔진에서 미검증 상태다. 실제 발생 이벤트가 없어 필수조치 배지를 임의로 붙이지 않았다. 기존 규칙은 유지했다.
- 작업방식 분기는 현재 API가 H05만 허용하고 세부 작업방식 입력이 없어 추가하지 않았다. Q023/Q024 등 비적용 질문을 강제로 노출하지 않았다.
- 평가에 실제 사용한 물질/물성값이 없어 MSDS 수치 대신 자료 없음 상태를 표시한다.
- 사고사례는 같은 작업ID 연결만 확인되며 개별 위험요인 일치라고 주장하지 않는다.

## 7. 추후 필요한 데이터/연결

작업방식 값과 질문 적용 관계, 개별 응답 상태 분류 기준, 조치 우선순위와 실제 강제경고 발생 결과, 평가 당시 사용물질 및 MSDS 값이 필요하다. 이번에 DB/API 필드 추가는 하지 않았다.

현재 API는 참고자료 원문을 반환하지 않으므로 기존 CSV 사본을 프런트엔드에 포함했다. 화면에 '현재 DB 참고자료이며 저장 당시 확정 근거 아님'을 명시했다. CSV 변경 후 아래 명령을 실행하고 프런트엔드를 다시 빌드해야 한다. 실시간 반영/평가 당시 근거 재현에는 추후 근거 API와 버전 스냅샷 설계가 필요하다.

```powershell
python frontend/scripts/sync-reference-data.py
```

## 9. 회귀 검증

`python -m unittest fire_risk_project.test_api -v`: 기존 5개 테스트 통과. 인증/CORS, 저장·재시작·중복 저장, 비교·만료, 계산 엔진 일치·조건부 질문, 잘못된 입력을 검증했다.

프런트엔드 폴더에서 테스트 API를 실행한 상태로 `node scripts/ui-check.mjs`를 재실행할 수 있다. 운영 DB를 대상으로 실행하지 말 것.

## 10. 빌드/실행과 남은 확인

Vite 프로덕션 빌드 통과. API 서버와 Vite 서버 기동 및 HTTP 응답 확인. 기존 Starlette/httpx 사용 중단 예정 경고 1종이 있으나 테스트 실패는 아니다.

이 도구 환경은 연결된 브라우저가 0개여서 실제 브라우저 클릭, 모바일 화면의 시각 검사, 브라우저 console error 검사는 수행하지 못했다. React 렌더링 검증과 반응형 CSS 적용은 완료했지만 시각적 무결성을 확인했다고 주장하지 않는다. 배포는 실행하지 않았다.
