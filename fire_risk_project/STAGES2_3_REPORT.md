## 2단계: 화재감시자 통합

### 실제 코드와 사진 차이

사진의 08번은 W004, 12번은 Q004입니다. 최신 코드에는 이미 W002/W003을 Q019/Q020와 중복 입력하지 않도록 정리한 변경이 있어 통합 전 화면상 위치는 06번·10번이었습니다. 통합 후 **06번 위치의 한 카드**에 배치 상태와 예외조건을 넣고, 총 9개의 번호를 순서대로 표시합니다. 내부 ID는 바꾸지 않았습니다. 사진 번호를 억지로 유지하여 빈 번호나 중복 질문을 만들지 않았습니다.

### 최종 입력 방식

- 카드 제목: **화재감시자 배치 및 예외조건 확인**.
- A: 배치 완료 → `응답.Q004=배치`, 미배치 → `미배치`, 배치 대상 아님 → `해당없음`, 확인 필요 → `확인불가`.
- B: 예외조건 충족(근거 확인 필요) → `화재감시자응답.W004=예`, 미충족 → `아니오`, 확인 필요 → `확인불가`.
- Q004 단독 카드를 제거했지만 질문 DB·S004·R002 연결과 과거 기록은 유지합니다.
- 입력상 장소조건이 모두 비해당이면 B를 숨기며, 숨겨진 이전 W004 선택은 반영하지 않습니다. 기록에는 W004 응답 null 및 `질문대상아님`을 저장합니다. 이를 예외 충족 또는 법적 비대상 확정으로 취급하지 않습니다.
- Q001/Q002의 거리조건(11m 포함), W001, Q019, Q020의 장소조건을 확인합니다. 현재 지원 작업 H05/R002 범위이며, 미확인 장소조건은 비해당으로 간주하지 않습니다.

### 점수와 판단

W004는 기존에도 점수에 직접 합산되지 않았습니다. Q004/S004는 미배치 3×2=6, 배치 0×2=0입니다. 통합 후에도 배치/미배치의 전체 요약·상세 점수는 이전 계산 결과와 같습니다. 예외 충족 응답만으로 Q004 점수를 낮추지 않습니다.

기존 S004의 '해당없음'은 0점·분모 제외 규칙이지만 기존 API도 근거 미검증으로 요청을 거부했습니다. 이번에는 '대상 아님'과 '확인 필요' 응답을 저장할 수 있게 하되 Q004의 점수·가중점수·분모, 전체 합계·위험지수를 null로 저장하고 **계산 보류**로 표시합니다. 다른 질문의 계산 결과는 보존합니다. 새로운 가중치나 안전한 0점은 만들지 않습니다.

입력 어댑터는 변경하지 않은 기존 엔진으로 다른 항목을 검증·계산한 뒤, 미확인 배치에 사용한 내부 임시 해당없음 값을 점수 보류 데이터로 교체합니다. 임시 계산의 지수·배치 응답은 저장하거나 화면에 보내지 않습니다. 이 과정은 `화재감시자입력.버전=integrated-v1`로 기록합니다.

법령 원문에서 예외가 별도 조건을 전제로 함을 확인했습니다: [국가법령정보센터 제241조의2](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1016870875). 기존 DB/입력에는 상시·반복 작업 및 필요한 설비의 현장 증빙을 검증할 자료가 없으므로, 실제 예외 충족이나 비대상을 자동 확정하지 않습니다. 배치조건 해당 응답, 미배치, 예외 충족 주장, 비대상 주장, 미확인을 구분해 안내합니다. 원문을 이유로 새로운 점수규칙이나 관련 없는 질문을 추가하지 않았습니다.

화면 응답 수는 카드가 아니라 활성 입력값 단위로 셉니다. 통합 A/B는 독립 입력 2개, 숨겨진 B는 0개입니다. 3단계 물질 선택은 활성화된 경우 하나의 추가 입력 그룹입니다. 예를 들어 거리와 B가 활성이고 물질 입력도 완료된 경우 11/11 응답입니다. 결과의 평가항목 수는 기존 점수 질문 기준이며, 확인 필요 수에는 관련 추가 조건·물질 확인 건수가 별도로 포함됩니다. 신규 기록에서 Q019/Q020와 파생 W002/W003의 확인 필요 중복 집계를 제거했습니다. 과거 기록은 당시 구조를 유지합니다.

## 3단계: MSDS DB 연결

### 실제 자료

연결 파일은 **`fire_risk_project/data/05_MSDS_물질DB.csv`**이며 16건입니다. 현재 체크아웃에는 별도 원본 Excel 파일이 없습니다. 파일 이름의 `05` 데이터셋을 직접 읽으며, 존재하지 않는 시트를 가정하지 않습니다.

사용 컬럼:

- 식별: `물질ID`, `제품명`, `제조사`, `CAS_No`, `용도`, `적용작업ID`.
- 분류/물성: `GHS인화성구분`, `인화점_기준값℃`, `인화점_연산자`, `인화점_원문`, `LEL%`, `UEL%`, `자연발화온도℃`, `증기압`, `증기압단위`.
- 주의사항/근거: `점화원주의`, `비고`, `물성근거URL`, `확인일자`, `근거유형`.

확인일자는 원자료를 보존하고 Excel 일련번호인 경우 화면에 ISO 날짜도 표시합니다. 인화점의 `≤`, `>`와 원문 표기를 보존하며 임의로 확정 수치로 바꾸지 않습니다.

명시적 가연성/인화성 분류 6건, 분류 확인 필요 9건, 선택 제외 1건으로 구분합니다. M001 산소는 DB상 비인화성/산화성 가스이므로 가연물로 선택할 수 없고, 별도 산화성 위험이 없다는 의미로 표현하지 않습니다. 인화성액체 분류 없음/제품자료 기준 등은 인화점 숫자가 있어도 확정 가연물로 분류하지 않습니다.

현재 작업의 주변 물질은 다른 작업용으로 등록된 제품일 수도 있으므로 `적용작업ID`로 전체 선택 목록을 좁히지 않습니다. 이 ID는 원자료에 보존하며, 해당 물질이 자동으로 현재 작업의 점수에 적용된다고 해석하지 않습니다.

### 입력·저장·화면

- 기존 거리 입력 바로 아래에 검색/드롭다운/복수 선택을 추가했습니다. 물질명·제조사·CAS로 검색하며 새로운 UI 라이브러리를 설치하지 않았습니다.
- 선택 제거·재선택, 목록 외 직접 입력, '가연물 종류 확인 필요'를 지원합니다. 확인 필요는 알려진 물질과 함께 선택할 수 있어, 일부만 확인된 현장도 기록할 수 있습니다.
- Q001 없음이면 거리/물질 입력이 비활성화됩니다. 물질 선택 상태를 초기화하고, 서버도 숨겨진 ID·직접 입력·미확인 상태를 반영하지 않습니다. 다시 있음으로 바꾸면 정상 입력할 수 있습니다.
- Q001에는 미확인 상태에 대한 기존 점수규칙이 없어 '확인 필요' 선택지를 추가하지 않았습니다. 선택하지 않은 존재 여부는 미입력이며 없음으로 바꾸지 않습니다.
- 물질 ID는 서버 CSV에서 검증합니다. 중복/미등록/선택 제외 물질을 거부하고, 직접 입력은 별도 MSDS 미확인 자료로 보존합니다.
- `가연물정보` JSON에 존재 여부·거리·선택물질 전체 스냅샷 배열·직접입력 배열·종류확인필요·확인필요수·DB 출처·파일 SHA256·조회 상태를 저장합니다. 클라이언트가 물성값이나 점수를 제출해 덮어쓸 수 없습니다.
- 결과의 **현장 가연물 정보**, **가연물별 취급·저장 주의사항**, 기존 **MSDS** 근거 영역에 저장 스냅샷을 사용합니다. 없는 물성이나 별도 예방조치는 'DB에 정보 없음'으로 안내합니다. 제조사 SDS·제품자료(PDS)·NIOSH 자료·MSDS 검색페이지를 동일한 자료로 취급하지 않습니다.
- DB 읽기 실패는 별도 목록 API 503과 화면 오류/재시도로 표시하며 기존 질문 페이지를 중단시키지 않습니다. 읽지 못한 등록 물질을 저장하려 하면 실패합니다. 직접 입력/종류 확인 필요로 명시적으로 기록하는 경우에는 조회 실패 상태를 함께 저장할 수 있습니다.

### 위험지수와 비교

점수 DB에는 MSDS 파생 규칙 S016(인화점 여유), S017(LEL 대비율), S018(발화온도 여유)이 있습니다. 그러나 현재 H05 사전평가 질문에는 연결돼 있지 않으며 기온·가스농도·장비 표면온도 등 필수 입력도 없습니다. 개별 물질 선택을 이 규칙에 임의 연결하지 않습니다.

따라서 **물질을 바꾸거나 여러 개 선택해도 기존 위험지수·질문별 점수·분모는 바뀌지 않습니다.** Q001/Q002의 기존 존재·거리 점수는 그대로 계산하고 물질 정보는 위험 특성 설명·실제 등록 주의사항·출처·확인 필요 항목에 사용합니다.

계산 엔진과 계산 데이터 해시는 그대로 유지되어, 숫자 산정이 가능한 구/신 기록은 기존 검증 조건에 따라 정량 비교됩니다. 미산정 배치 기록은 기존 비교 제한으로 처리합니다. 자료만 바뀐 MSDS 해시는 점수 계산 해시와 분리했습니다.

자동/수동 비교에 가연물 존재·거리·물질명·확인 필요 상태를 추가로 보여주되 물질명 변경 자체를 개선/악화로 판정하지 않습니다. 과거에 물질을 기록하지 않았다면 '당시 물질 종류 정보 미기록'으로 표시하며 현재 DB에서 선택 정보를 채우지 않습니다.

브라우저 검사에서 점수와 미산정 기록이 섞일 때 목록의 빈 값이 Pandas NaN이 되어 JSON 오류가 나는 문제를 발견했습니다. null 변환으로 수정하고 API/실제 브라우저 회귀 검사를 추가했습니다. 브라우저 검사 도구의 DOM 대기값 및 개발 모드 취소 요청 처리도 보완했습니다. 최종 재검증에서 남은 실패는 없습니다.

## 남은 한계

실제 현장 증빙이 없어 화재감시자 법적 예외·비대상 여부를 자동 확정할 수 없습니다. '대상 아님'은 실제 배치 여부까지 알려주는 응답도 아니므로 안전한 점수로 대체하지 않습니다.

MSDS DB 일부는 실제 공급제품이 미정이거나 물성·출처가 비어 있으며, 일부는 SDS 대신 제품자료·대표물성·검색페이지입니다. 제품별 전체 유해성 분류와 상세 보관·예방조치가 모두 있는 자료가 아니므로 없는 정보는 추가하지 않았습니다. 물질 검색 결과는 현장 제품 동일성을 자동 검증하지 않습니다.

운영 DB/배포 환경에는 접근하거나 테스트 기록을 쓰지 않았습니다. 테스트는 임시 SQLite에서 수행했으며 Postgres 실서버 검증은 하지 않았습니다. 기존 Render `DATABASE_URL`→Supabase/Postgres 구성이 영구 보관에 필요하고, Render 임시 SQLite 파일의 영구성을 보장하지 않습니다. 기존 공용 접속 키 인증과 사용자 간 공유 범위도 그대로 유지했습니다.
